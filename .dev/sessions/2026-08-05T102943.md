Several small convention gaps closed, two larger ideas documented for later, surfaced while comparing agentics' own design against an unrelated AI-coding-tools discussion.

- `template/conventions/convention-levels.md` § Checking for upstream updates: the classification step only ever checked whether a new agentics entry formalizes something a project's memory already tracks informally (duplication). Added the missing other case: a new entry that contradicts what memory recorded as settled, surfaced as a real conflict rather than silently resolved either way.
- `testing/scripts/check-consistency.sh`: added a mechanical check scanning commits ahead of the configured upstream (or just `HEAD` with none configured) for AI-tool attribution trailers (`Co-Authored-By`, `Generated with`, etc.), closing the gap where `session-discipline.md`'s absolute rule against them had no script backstop.
- `README.md`: added "The illusion of context" between the opening pitch and "Quick start", framing in human terms what an agent "understanding" a codebase actually requires, context that survives past the session that created it, rather than comprehension agentics doesn't claim to give.
- `AGENTS.md` (root and template): added a new Interaction parameters bullet, externally-sourced content that overlaps with a project you maintain gets named unprompted, the same instinct as the existing "surface ideas unprompted" bullet, applied to material arriving from outside the current project.
- `template/conventions/review-conduct.md` § "Push back, including on yourself": a generated list of options, features, or specs now gets its feasibility triage (solid, needs-narrowing, aspirational) as part of producing it, not only when asked which items are unrealistic.
- `CHANGELOG.md` and `testing/regression-checklist.md`: entries added for each fix above.
- `testing/consistency-checks.md`: caught during this release's gap-scan, still documented only 6 checks after `check-consistency.sh` gained a 7th (the AI-attribution scan) earlier in this same batch; added the missing entry and renumbered the one after it.
- `.dev/roadmap.md`: documented two not-yet-designed ideas under "Design questions": backfilling lessons learned from decisions already sitting in closed PRs, resolved tech-debt entries, or old issue threads that never made it into memory or `.dev/docs`; and a generalized "vault" memory pattern (a behavioral gate, exclusion from the auto-loaded memory index, or real passphrase-based encryption at rest, three distinct tiers of protection, not one mechanism).
- `template/conventions/code-style.md` § "Non-mutational": named the rule's actual target (accumulation as a substitute for computation) explicitly, and carved out a narrow, verification-gated exception for a mutable signal recording an async event (a cancellation flag), surfaced by a real cleanup-function mutation wrongly flagged as a violation.
- `template/conventions/code-style.md` § "Dependency version verification": added that a wrapper's current type signature isn't proof the dependency underneath it lacks a capability either, surfaced by the same incident: a fetcher wrapper was assumed to lack cancellation support until the HTTP client it actually called into (already a dependency) turned out to support it natively.
- `template/conventions/writing-style.md`: added "Addressing the user", using the developer's known name in conversational replies and visible reasoning rather than the generic "the user," with direct address ("you") as the fallback when no name is known. Scoped to live, ephemeral output only; persisted content keeps the existing "Name code, not people" rule.
