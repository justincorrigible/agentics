A live incident in a different adopting project surfaced a gap one step earlier than an existing safeguard already caught, plus several smaller fixes and a new opt-in roadmap/atlas feature driven by real team feedback.

- `template/conventions/convention-levels.md` § Checking for upstream updates: an agent noticed its project's agentics tag was stale, then moved on to other work without ever running the diagnosis, treating the notice itself as the completed check. The existing guard only caught stopping after the diff but before the diagnosis; added a paragraph stating that detecting staleness obligates running the rest of the procedure in the same sitting, or explicitly saying it's being deferred.
- `template/conventions/upgrading-adoption.md` § 1: the no-synced-value path's "bounded catch-up" from agentics' own `## Unreleased` section produces nothing when a first-time sync happens to land right after a release, exactly when a brand-new adopter has the most to catch up on. Added a fallback to the latest `## Released` version's entries when `## Unreleased` is empty. Found while reviewing further output from the same helm-charts/infra session.
- `template/conventions/code-style.md` § "Non-mutational": the rule read as an optional preference in practice, not an enforceable one, despite already having concrete examples and a named exception. Added a per-line trigger (default to `const`, treat every `let` as a question to answer) and an "Optional automated enforcement" note recommending ESLint's `prefer-const`, verified first that it isn't part of `eslint:recommended`.
- Real team feedback: `.dev/roadmap.md` served as both agent-queried memory and a human-facing artifact with no split between the two, one person diverging toward reading it directly and finding it overwhelming. Added an opt-in `roadmap_split` initialization question (`template/AGENTS.md` § Initialization, now 7 questions): when set, deeper roadmap reasoning routes to `.dev/docs/atlas/roadmap/<topic>.md` instead of staying inline in `.dev/roadmap.md`, and turning the flag on is itself a migration, existing dense entries get swept and relocated in the same pass, not just new ones going forward. Formalized `.dev/docs/atlas/` in `documentation.md`: a required index and plain relative-link cross-referencing between topics, nested under `.dev/docs` rather than replacing its top level or standing alongside it as a new `.dev/` folder, so a project's own pre-existing, human-curated service folders directly under `.dev/docs` stay completely untouched. `definition-of-done.md`'s lessons-learned criterion now defaults substance without an obvious existing home to the same atlas location. Default stays off; agentics' own roadmap is a deliberate non-adopter. `template/DEVELOPMENT.md` updated to match.
- Refined the earlier scratch-tier design question in `.dev/roadmap.md`: moved from a harness-specific temp path to project memory space instead, so it works for any agent with persistent project memory, not just Claude, and added a new angle, letting a concurrent or later session pick up a just-learned lesson before it's been judged worth a formal memory entry.
- `template/conventions/session-discipline.md` § Git: nothing addressed commit-message content or quality, only staging permission and AI-attribution. Added "Writing the message itself": succinct by default regardless of a repo's own past verbosity, matching an existing repo's history covers format only (type prefix, capitalization), not length; a user-visible-effect subject, a short prose why-focused body, honest one-clause disclosure of any bundled unrelated fix, staging scoped to match.

Added an explicit exception for `CHANGELOG.md`'s own `## Unreleased changes` heading: it's the canonical, actively-maintained source of that fact, not a driftable duplicate of one tracked elsewhere, so it isn't the same violation.
