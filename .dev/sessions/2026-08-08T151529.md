Learned about Claude Code's cross-session messaging (`ListAgents`/`SendMessage`) and connected it to three already-parked design questions rather than letting the insight sit only in conversation.

- `.dev/roadmap.md` § "Agent manager": cross-session messaging directly answers the "actual mechanism" question this item left undesigned, and its own design (a message never counts as consent, the receiving session's normal permission prompts still fire) already satisfies the developer-review concern too. Real constraint noted: both sessions must be concurrently running, this accelerates the case where a relevant session is already open, it doesn't replace devctx/memory for the general case.
- `.dev/roadmap.md` § "Cross-pollination of expertise": same mechanism could remove the manual-relay step when both sessions happen to be open, letting the source session hand a finding directly to a concurrently-running target session instead of the developer relaying it by hand.
- `.dev/roadmap.md` § volatile-facts tier: the "concurrent session discovers a draft" open question now has a plausible direct answer, messaging a peer session on the same project when a draft is written, rather than relying on that session to independently notice it.

Not implemented, nothing used yet: this is a newly-learned capability connected to existing open questions, not a design commitment.
