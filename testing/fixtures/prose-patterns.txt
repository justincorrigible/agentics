# the run, so the two columns are equally load-bearing: a pattern with no PASS cases has not
# been shown to discriminate, only to fire.
#
# This file lives outside template/ and docs/, so the corpus scans never read it and the
# instances below need no quoting or exclusion. Add a case here before changing a pattern,

# all run before a pattern sees the corpus, each is length-preserving so that offsets survive,
# and two shipped defects lived in that layer rather than in any regex. A case here passing says
# the pattern discriminates, never that the check is correct end to end.

# ONE PROPERTY, FOUR FACES. Every false positive found in these patterns so far is the same thing:
# a pattern matches words and cannot see the situation the sentence sits in. Stated once here, with
# its faces under it, so the fifth is predicted rather than discovered as a surprise. It accumulated
# as three separate exclusions each with its own story before anyone noticed they were one property.
#
#   face                                    example                              excludable by pattern?
#   a property of the system                "worth having"                        yes, it has a fixed word
#   the reader's own future writing         "if it is worth stating, state it"    no
#   where content should go                 "attribution belongs in git history"  no
#   where something sits in the system      "`plane` lives here, not per row"     no
#
# Only the first can be excluded. The other three are the reading step, which is why a pattern of
# this family ships as candidate-raising and never as a defect count.
#
# THREE VERDICTS, because PASS is nearly unreachable for this family: only the one face with a
# fixed word can ever be correctly refused.
#   PASS  the pattern must not raise the line at all.
#   KEEP  it must raise the line AND the line is a real instance that stays as written.
#   KNOWN it must raise the line AND the line is not a real instance, and no pattern can tell.
# KEEP and KNOWN are identical in what they demand of the pattern and differ only in what the
# reader concludes. Both mean: never narrow the pattern to silence this flag. Filing a keeper as
# KNOWN asserts it is a false positive, which is the opposite of what a keeper is.
#
# WHAT A CLEAN RESULT HERE DOES NOT MEAN. This file's own placement cases come back four for four
# as keepers, and that is a fact about this corpus rather than about the pattern: the pattern
# fires on a sentence where the location word points at the system instead of the file, and this
# corpus simply contains no such sentence. A corpus describing a schema would produce them. The
# mandatory deictic is what keeps the other faces out, and it is exactly what lets that one in. Pinning those matters: without them, someone narrows the pattern to stop it
# flagging a known-good line and silently loses the genuine candidates that share its shape.
